Here is a breakdown of how the current code works, followed by a guide on how to port this to Next.js using OpenRouter's free vision models.

How the Current Code Works (The Pipeline)
Image Ingestion (Drag & Drop / Upload)

When you drop an image, the handleFile function uses the browser's native FileReader API.

It reads the image and converts it into a Base64 string (a text representation of the image data), which is required to send images over standard HTTP JSON requests.

AI Vision Extraction (processImageWithAI)

The app constructs a prompt specifically instructing the AI to act as a data extractor and return only a JSON object.

It sends the prompt and the Base64 image directly to the Gemini API (gemini-2.5-flash-preview).

Crucial step: It uses responseMimeType: "application/json" to force the AI to return valid, structured JSON instead of conversational text.

Data Parsing & State Update

Once the AI returns the JSON, the code parses it, generates a unique ID (crypto.randomUUID()) for each event, and assigns a random color theme from the colorMap.

This data is saved to the React events state.

UI Rendering (The Calendar Grid)

The calendar is a CSS Grid. The tricky part is positioning the events.

It calculates the vertical position dynamically: top: (event.start - 8) * 96 pixels. (Since the calendar starts at 8:00 AM, 9:00 AM is 1 hour down. If 1 hour = 96px, 9:00 AM starts at 96px from the top).

Height is calculated similarly: height: event.duration * 96 pixels.

ICS Export (downloadICS)

To make it importable to Google Calendar/Apple Calendar, it constructs an .ics text file.

It finds the date of the next upcoming Monday and maps the day integers (0 for Monday, 1 for Tuesday) to actual real-world dates and times.

It formats this into standard iCalendar syntax (BEGIN:VEVENT, DTSTART, etc.), creates a virtual file (Blob), and forces the browser to download it.

How to build this in Next.js with OpenRouter
The biggest architectural change when moving to Next.js is that you should never call AI APIs directly from the frontend (client-side). Doing so exposes your API key to anyone who inspects the website. Next.js solves this with API Routes (running securely on the server).

Here is the step-by-step pipeline for Next.js:

1. Setup Next.js
Run npx create-next-app@latest timetable-app in your terminal. Accept the defaults (using App Router and Tailwind CSS).

2. Create the Backend API Route
Create a new file at app/api/extract/route.js (or .ts). This is where OpenRouter is called securely. OpenRouter uses the exact same format as the OpenAI API.

JavaScript

// app/api/extract/route.js
import { NextResponse } from 'next/server';

export async function POST(req) {
  try {
    const { base64Image } = await req.json();

    const response = await fetch("https://openrouter.ai/api/v1/chat/completions", {
      method: "POST",
      headers: {
        "Authorization": `Bearer ${process.env.OPENROUTER_API_KEY}`,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        // You can use a free vision model like google/gemini-2.5-flash via OpenRouter
        model: "google/gemini-2.5-flash", 
        response_format: { type: "json_object" }, // Ask for JSON
        messages: [
          {
            role: "user",
            content: [
              {
                type: "text",
                text: `Extract the schedule from this image. Return STRICTLY JSON with a single array property called "events".
                      Each object must have: title (string), location (string), day (integer 0-4 for Mon-Fri), start (float 24hr format, e.g. 9.5 for 9:30), duration (float in hours).`
              },
              {
                type: "image_url",
                image_url: {
                  url: `data:image/jpeg;base64,${base64Image}`
                }
              }
            ]
          }
        ]
      })
    });

    const data = await response.json();
    
    // OpenRouter returns the text inside choices[0].message.content
    const jsonString = data.choices[0].message.content;
    const parsedData = JSON.parse(jsonString);

    return NextResponse.json(parsedData);

  } catch (error) {
    console.error("API Error:", error);
    return NextResponse.json({ error: "Failed to process image" }, { status: 500 });
  }
}
3. Store your API Key
Create a .env.local file in the root of your Next.js project and add your OpenRouter key:

OPENROUTER_API_KEY=sk-or-v1-your-key-here
4. Update the Frontend (page.js)
You will copy the App.jsx UI code into your Next.js app/page.js. However, you will change the processImageWithAI function so it talks to your own local Next.js API route instead of the external AI service directly.

// Inside your Next.js client component (make sure to add "use client"; at the top)

const processImageWithAI = async (base64Data) => {
  setIsProcessing(true);
  setError(null);

  try {
    // Call YOUR Next.js secure backend
    const response = await fetch('/api/extract', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ base64Image: base64Data })
    });

    if (!response.ok) throw new Error("Backend failed");

    const parsedData = await response.json();
    
    if (parsedData.events && Array.isArray(parsedData.events)) {
      const mappedEvents = parsedData.events.map((ev) => ({
        ...ev,
        id: crypto.randomUUID(),
        color: colorKeys[Math.floor(Math.random() * colorKeys.length)]
      }));
      setEvents(mappedEvents);
    }
  } catch (err) {
    setError("Failed to extract schedule. Please try a clearer image.");
  } finally {
    setIsProcessing(false);
  }
};

The error you are seeing (Model returned malformed JSON) is very common when working with free or smaller LLM models via OpenRouter.

What went wrong:
Instead of returning a single JSON object containing an array (like { "events": [ ... ] }), the model got confused and returned a raw, comma-separated list of objects: {}, {}, {}. When JSON.parse() tries to read this, it crashes because {}, {}, {} is not valid JSON syntax on its own.
